# 工程规范与交付门槛

工程化是项目必须满足的交付条件。P1–P5 的包、依赖锁、检查、迁移、浏览器验证和流水线配置已实现，证据见 [P5 验收记录](P5_ACCEPTANCE.md)。本文还包含 P6–P8 的持续要求；尚未实现模型长任务或 MCP，不能将这些未来约定当作当前能力。

这些要求从 P1 的第一个可运行产物开始执行，随功能增加对应测试和发布检查。P8 汇总回归与正式交付；逐阶段任务见 [实施路线](ROADMAP.md)。

## 安装和依赖

- 使用标准 Python 包和 `src` 布局；依赖与可选功能集中声明在 `pyproject.toml`，提交 uv 锁文件。
- 运行、开发、GUI/截图和 AI 接口依赖明确分组，避免仅查询材料也必须加载浏览器。
- 正式运行使用已打包前端静态资料；开发环境前端依赖有独立锁文件，禁止靠外部 CDN 才能打开本地设计。
- 每次发布验证干净环境安装、wheel 内容、CLI 帮助和基本创建/导出。打包产物包含所需静态界面，不能只在源码目录运行。
- 不直接依赖旧项目的 Node 包，也不复制 `node_modules`、临时研究目录或用户缓存作为环境。

## 代码和边界

- 关键公共函数有类型；输入输出有版本化契约，领域逻辑不混在路由/CLI 文件。
- 使用 Ruff 格式和 lint、mypy 类型检查；前端 TypeScript 检查与格式规范独立执行。
- 未验证的数据先经过边界校验；未知字段、材料和属性提供明确错误，不静默忽略。
- 统一错误结构：错误码、可读原因、字段/对象位置、请求 ID、设计修订和可恢复信息。返回失败不能标为完成。
- 禁止裸 `except` 吞错、隐式全局工作区、路径写死或无依据的大范围补丁。
- 所有入口调用同一应用服务；通过依赖检查验证核心不反向依赖接口与旧项目。

## 数据与恢复

- 每次编辑原子提交数据与历史，修订冲突不覆盖新稿；重试有幂等标识。
- 数据 schema、API 和资源版本分别管理，迁移前备份，迁移失败保留可恢复原件。
- 测试异常退出、提交中断、数据库锁、资源缺失、文件损坏和重复请求后的状态。
- 导出文件先完整生成并校验后交付；禁止生成半份文件并报告成功。
- `.litematic` 的长整数、NBT 标签类型、多区域与未知内容按已声明的能力保留；所有有损输出须显式报告。
- 编辑“完整方块状态”与实体/NBT 内容分别建模，不能把告示牌文字当作普通属性。

## 测试

| 层级 | 验证目标 |
| --- | --- |
| 单元 | 选区、坐标、旋转/镜像、方向属性、状态规则、历史行为 |
| 契约 | CLI/HTTP/MCP 的同一请求产生同一语义结果；错误与版本一致 |
| 集成 | 存储原子性、重开、迁移、幂等重试、格式读写和资源导入 |
| 端到端 | 真正操作三维界面选区/修改/撤销，截图反馈，最终资产导出 |
| 交叉核对 | 与独立解析器/参考样例对照坐标、完整状态和 NBT 内容 |
| 性能 | 固定数据规模下的载入、局部编辑、材质替换、保存、渲染、导出和内存 |

不能仅用导出器自己的解析代码验证自己。不得把 mock 测试声称为真实浏览器或 Litematica 客户端验收。

视觉验收检查材质、方向、开口、透明、连接与剖切，不用美观打分替代正确性。AI 审美效果另做记录，不能由测试全绿推断。

## 配置、日志和任务

- 配置有 schema、默认值、优先级和示例；用户路径与项目数据可移动。
- 使用标准 logging 和结构化事件，包含请求 ID、项目、修订、任务和耗时。普通日志不输出模型凭据或整栋建筑。
- 耗时任务有可查询状态、进度、超时和取消，渲染失败返回实际错误，不能无限等待。
- 模型凭据由环境或用户配置提供，与项目资产分开；本阶段没有模型服务配置需求。
- 临时文件与缓存有明确所有者、关闭/失败清理和大小上限；不能把资源缓存误当用户项目清理。

## CI 与发布

初始支持 Windows 和 Linux 的 Python 3.12。CI 应执行依赖锁定安装、格式/lint/类型、单元/契约/集成、前端检查构建和 Python wheel 安装冒烟。浏览器验收至少在一个固定环境运行，另记录 Windows 的实际桌面/浏览器验证。

提交必须有与变更匹配的验收证据。修改共享格式或资源规则时同时检查导入、编辑、预览与导出消费者；不能只检查本次入口。

仓库包含源码、小型来源明确的样例、文档与必要配置。用户项目、大型模型贴图、临时导出与本地日志通过声明的数据/缓存目录管理。资源清单记录来源和使用条件，发布包不得含未确认可分发的第三方资产。

独立 Git 仓库、uv/npm 锁文件及 CI 配置已建立，Windows/Linux 安装检查已在本地执行。GitHub Actions 尚未在远端执行；当前 wheel 为交付点 A 的本地构建产物，正式发布与 AI 验收仍属于 P8。
