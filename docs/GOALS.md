# 项目目标与完成定义

制定日期：2026-10-09。实现状态以 [实施路线](ROADMAP.md) 的阶段表为准。

## 总目标

在 `D:\Study\program\Design_workbench` 建立独立、可安装、可维护的 Minecraft 建筑设计工作台。Python 维护权威方块场景、编辑事务、材料资源与蓝图资产；浏览器提供实际 MC 方块的三维编辑；人和 AI 使用同一套服务完成创建、预览、修改、保存和导出。

最终支持自然语言需求驱动的 AI 设计：查询材料、规划结构、批量生成、查看实际多角度画面、局部改稿、保留版本、导出 `.litematic`。每一步可追溯、可撤销，模型调用有预算；大型目标由平台保存，不要求模型一次逐格输出整栋建筑。

当前 P1–P6 已实现并验收，交付点 A/B 达成。G6 的 CLI/HTTP/MCP 工具、真实图像反馈与实际外部 AI 流程已通过，见 [P6 验收](P6_ACCEPTANCE.md)；G7 的平台内自主模型调用仍待 P7。P6 交付不代表全项目最终完成。

## 优先级

1. 工程可靠性：独立运行、数据正确、事务恢复、模块边界、可重复验证。
2. 设计工作台：版本材料、实际外观、可靠编辑、蓝图读写。
3. AI 可操作性：材料查询、局部结构与图像反馈、稳定工具契约。
4. 自主设计效果：需求符合度、空间结构、人工审美反馈与成本。

前一层未通过对应验收，不把后一层的演示作为其完成证据。工程检查从第一个可运行阶段开始，每个阶段都执行。

## 范围基线

- 首个正式游戏版本：Minecraft Java 1.20.1。新增版本分别建立资料与验收，不通过修改版本字符串宣称兼容。
- 项目以 Python 为核心，三维浏览器界面采用 TypeScript/Three.js；打包运行无需开发用 Node.js。
- 全量注册方块目录可核对；模型、贴图、特殊内容的预览支持分别标记。首版目标是常用建筑静态外观可信，以及所有条目的支持范围透明。
- 既有建筑可以作为导入资产和回归样例；构件与几何工具支持创作，不把设计限制在固定成品房型。
- 当前范围不包含 Blender 集成、文生/图生 3D、bot 施工、游戏服务器接入、完整游戏物理或多人实时协作。行走精修 E1 已实现，用户网格体素化 E2 未开始；两者见 [扩展计划](PLANNED_EXTENSIONS.md)，不替代交付点 B/C。

## 素材已有基础

旧原型的小屋和教堂使用 mcblock.top 预览所用的公开渲染资源资料，本地已保存模型、状态显示定义、纹理图集与兼容映射。小屋两稿所需 22 张纹理、教堂所需 51 张纹理的查找均未报告缺项。

这些结果证明旧案例已有静态显示基础。新项目已复用解析经验，单独导入官方 1.20.1 客户端模型、贴图与语言文件，并建立资源清单及全状态覆盖报告。实际运行使用官方版本一致资源，旧网站混合版本包不作为运行依赖；详见 [资源与限制](RESOURCES_AND_LIMITS.md)。

旧路径只作为迁移证据，不成为新项目的运行依赖。资源包进入独立管理目录后记录来源、哈希、声明版本及核对状态。

## 效果与性能的边界

AI 审美不承诺所有建筑风格全覆盖。记录比例、轮廓、立面、材料搭配、入口与内部空间等人工评价，同时记录需求约束是否满足；模型自评分不充当完成证据。

性能使用小型建筑、36,094 格教堂和 100,000 格扩展样例。教堂是首版必测规模；100,000 格用于探索扩展能力，未通过时不影响明确限制为较小规模的版本交付。P4 记录目标机器基线并确定发布门槛，P5/P8 按预先记录的门槛复测，不事后修改门槛解释失败。

每次验收注明目标版本、机器、资源包、数据规模、修订和测试方式。真实浏览器、独立格式核对和实际模型运行与 mock 结果分开记录。
