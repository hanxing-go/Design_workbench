# 自动放置与挂画

核对日期：2026-10-12。放置、邻接与精确编辑详见 [放置规则](PLACEMENT_RULES.md)；版本范围见 [多版本支持](VERSION_SUPPORT.md)。

## 使用

左侧材料面板共用一个「自动朝向与贴合」开关，默认开启。选择材料后点击方块表面，按点击位置、视角和实际支撑决定朝向、上下半部和壁挂形态。相邻连接、双格结构由同一次事务更新。

选择形态按钮或高级属性会切换到手动模式，保留所选状态；手动模式仍检查实际支撑和碰撞。精确悬空结构使用 `set` 编辑接口。地面网格是 Y=0 的起笔平面，不会作为真实方块导出。

旧的「自动吸附」开关已合并到材料面板，避免两个设置互相矛盾。现代 `place` 请求使用 `hit`、`normal`、`location`、`facing`、`automatic`；旧的 `support` / `face` 请求仍由接口兼容转换，并检查支撑。

## 画

在左侧「画」中选择图案，点击「选择画」，再点击竖直墙面。朝向跟随点击面。当前固定图案集合包含 Java 1.20.1 的 30 种官方图案，尺寸从 1×1 到 4×4；其他受支持游戏版本也使用此集合，尚未扩充新版新增图案。「自动」按可用空间选择最大图案，同面积采用固定顺序。

画需要完整支撑和前方空格，不能重叠、越界或覆盖受保护内容。新增画支持拾取、删除、保存、撤销、重做与重开。删除模式点击画只移除画，保留墙面；修改支撑前需要先删除受影响的画。画暂不参与方块分组、选区移动、复制、旋转与阵列。

预览使用官方贴图的静态平面；导出写入 `minecraft:painting` 实体，包括 variant、facing、TileX/Y/Z、Pos、UUID。导入的已知画作为只读实体预览并保留原始 NBT，其覆盖格与支撑格受到保护。未知图案保留数据但不预览。游戏内 Litematica 验收尚未完成。

## 接口和持久化

以下操作沿用 `EditRequest` 的 schema_version=1、expected_revision 与 request_id：

| op | 字段 |
| --- | --- |
| painting | support 整数坐标；face 为 north/south/east/west；variant 默认 auto 或图案名 |
| delete_painting | 新增画的 UUID id |

`GET /api/paintings` 返回图案名和尺寸。增量 render 包包含 `paintings`，即使方块 chunk 未变化也会更新挂画。项目 SQLite schema=3，从旧 schema 打开时备份并迁移。图集配方升级到 5，已有素材从本地缓存重建，无需重新下载客户端。

集成测试覆盖空间检查、原子失败、持久化、撤销重做、schema 迁移、独立 litemapy 导出读取、负原点与四种朝向。真实 Chrome 覆盖自动/手动放置、挂画显示、画布像素、导出、重开及删除。
