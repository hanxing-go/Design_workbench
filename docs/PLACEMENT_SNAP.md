# 自动吸附与挂画

核对日期：2026-10-10。当前按 Minecraft Java 1.20.1 / DataVersion 3465 验证。

## 使用

左侧材料属性上方新增「自动吸附（放置时按支撑面定向）」，默认开启。选择材料，再用「放置」点击已有方块的表面：目标是该表面外侧相邻的一格，朝向和必要的材料形态由支撑面决定。目标已有方块、支撑消失、空间越界或含受保护内容时，整次编辑失败。

吸附只修改这次放置的状态，不覆盖面板里的手动属性。取消勾选后继续使用既有手动放置：例如把梯子的 facing 预设成 west，开启吸附时可以贴到南墙，关闭后仍按 west 放置。手动模式允许制作不满足游戏放置规则的静态设计。

地面网格是工作台 Y=0 的起笔平面，用来开始新建筑；它不是导出蓝图中的真实支撑方块。

| 材料 | 自动调整 |
| --- | --- |
| 普通、灵魂、红石火把 | 顶面用落地形态；侧面切换对应壁挂形态并设 facing；底面拒绝 |
| 全部 11 种木材的告示牌 | 顶面用立式；侧面用 wall_sign；水浸状态保留；底面提示改用悬挂告示牌 |
| 悬挂告示牌 | 侧面用 wall_hanging_sign；底面用 hanging_sign，设置 rotation/attached；顶面拒绝 |
| 梯子 | 四个侧面自动设 facing；顶面、底面拒绝 |
| 按钮、拉杆、砂轮 | 自动区分 floor/wall/ceiling 与 facing |
| 灯笼、灵魂灯笼 | 顶面放置或底面悬挂；侧面拒绝 |
| 活板门 | 设置 facing；侧面按点击的上下半部设 half，顶面/底面也自动设 half |
| 末地烛、避雷针、紫水晶簇及晶芽 | 按六个支撑面设 facing |
| 藤蔓 | 根据侧面或底面设置对应连接属性 |
| 其他材料 | 仍放到点击面相邻格；保留手动材料状态 |

立式告示牌、顶面/底面的按钮等，水平朝向根据相机方向取四个主方向；需要精确的 16 档 rotation 时关闭吸附手动设定。吸附没有自动修改其他相邻方块的连接状态。

## 画

画是实体，不是注册方块。在左侧「画」中选图案后点击「选择画」，再点击墙面。支持官方 30 种图案，包括 4 种不在普通随机挂画集合里的元素画，尺寸从 1×1 到 4×4；选择「自动」时按可用空间选最大尺寸，同面积图案采用固定顺序，便于重复操作和验收。

画需要完整的背后支撑和前方空格，不能重叠、越界或覆盖受保护内容。开启吸附时朝向跟随点击墙面；关闭时用独立的「手动朝向」。手动朝向对应的墙面仍必须实际存在，不允许悬空挂画。

新增的画可拾取、删除，支持自动保存、撤销、重做及重开；删除模式点击画只删除画，保留墙。画存在时修改其支撑或占用其前方空间会失败，需要先删除画。画暂不参与分组和方块选区的移动、复制、旋转与阵列。

预览使用官方 painting 贴图的静态平面，尚无游戏内的边框厚度、背面材质及光照细节。导出写入真正的 `minecraft:painting` 实体，包含 variant、facing、TileX/Y/Z、Pos、UUID 等字段；不是用图片方块替代。客户端粘贴蓝图时需要启用实体处理，工作台尚未完成 Minecraft/Litematica 游戏内验收。

导入蓝图中的已知画可预览，但继续作为原始 NBT 的只读实体保留。画的覆盖格和背后支撑格受保护；不转换成可编辑画，避免重复导出。未知画图案保持原始数据，当前不会预览。

## 接口和持久化

新增三种操作，均沿用 `EditRequest` 的 schema_version=1、expected_revision 与 request_id：

```json
{
  "schema_version": 1,
  "expected_revision": 1,
  "request_id": "attach-torch",
  "operations": [
    {
      "op": "place",
      "support": [0, 1, 0],
      "face": "south",
      "heading": "north",
      "hit_height": 0.5,
      "ground": false,
      "state": {"name": "minecraft:torch"},
      "group": "main"
    }
  ]
}
```

上例要求 [0,1,0] 有真实支撑，在 [0,1,1] 放置 facing=south 的 wall_torch。

| op | 字段 |
| --- | --- |
| place | support 整数坐标；face 为六向；heading 为水平四向，默认 north；hit_height=0..1，默认 0.5；ground 默认 false；state、group |
| painting | support；face 限水平四向；variant 默认 auto，或官方图案名 |
| delete_painting | 新增画的 UUID id |

`GET /api/paintings` 返回图案名和尺寸。render 包新增 paintings 列表，每次返回最终列表；新增画不改变方块 chunk_versions。编辑响应新增 paintings_changed=0/1，表示列表是否变化；原有 changed 仍是方块变化格数。preview 返回最终画列表，提交时重新验证所有条件。

SQLite schema 从 2 升为 3。画保存在 scene 元数据，与分块、历史、请求指纹共用事务。schema 1/2 打开前分别创建 `.v1-backup-*` / `.v2-backup-*`，迁移保留既有元数据和原始附件；没有画的旧项目按空列表读取。旧 schema=2 程序会拒绝打开升级后的项目，应使用升级前备份进行旧版检查。

新画的前方空间计入导出的区域包围盒，实体坐标相对于所属区域的规范化 low。延续蓝图导出对重叠区域的限制：新增内容的包围盒如果与原区域产生歧义，报 EXPORT_REGION_OVERLAP，不静默拆分或覆盖。

## 实现边界与验证

Python 领域层决定吸附形态和占用空间，注册表再校验材料及属性；浏览器只提交点击面、点击高度和相机方向。保留原有 set 操作和手动入口，避免模型/UI 各维护一套吸附规则。

支撑检查是保守的离线策略：完整、稳定的实体块及完整玻璃等可作为支撑；半砖、楼梯、栅栏和其他局部模型不推断可用面。部分游戏内合法放置可能被拒绝，关闭吸附可继续手动编辑。工作台不执行完整 sturdy-face、重力、红石、流体、掉落或实体更新规则，导出成功不是游戏内存活证明。

验证覆盖三个火把系列、所有告示牌形态、代表性附着材料、手动设置不被改写、支撑与碰撞失败、请求重试、画的空间检查/删除/持久化/撤销/重做、schema 2 迁移备份。真实浏览器点击墙面放置火把、梯子、告示牌和画，并读取实际画布像素、重开、删除及导出。画的实体输出通过独立 litemapy 读取，另检查负原点、四种朝向、区域相对坐标与 UUID 保留。

本机 Windows 全量 pytest 为 51 项通过，包含官方资源与真实 Chrome；Ruff、strict mypy、TypeScript、Prettier 与前端构建通过。截图留在本机 `artifacts/snap/wall-snap.png`，不上传游戏素材。
