# 扩展计划：行走精修与网格体素化

制定日期：2026-10-09。更新日期：2026-10-10。状态：E1 已完成，见 [验收记录](E1_ACCEPTANCE.md)；E2 未开始。两条计划都依赖已完成的 P5，不依赖 P6–P8，也不改变交付点 A/B/C 的完成定义。P6 的独立进度见 [实施路线](ROADMAP.md)。

详细行为以本文为准。阶段状态仍记在 [实施路线](ROADMAP.md)。当前已实现范围见 [当前能力](CURRENT_CAPABILITIES.md)。

## 和现有范围的关系

行走精修改变的是观察和落笔方式，场景、修订和导出格式保持不变。网格体素化是一条新的导入：用户已经有三角网格，程序把它变成可逐格编辑的方块，再沿现有 Litematica 路径导出。

文生 3D 和图生 3D 仍不进入实现。本计划不从文字或图片生成网格，不调用外部生成服务，也不把 Blender 当作运行依赖。用户用任何工具导出 OBJ 或 glTF 之后，再交给工作台。

参考只说明公开可见的交互和流水线：

- 第一人称飞行是常见的创造模式操作。Cubical 不公开源码，E1 在现有 Three.js 查看器上自行实现。
- [ObjToSchematic](https://github.com/LucasDower/ObjToSchematic) 1.0 以 BSD-3-Clause 公开了「读网格、光线体素化、取色、抖动、匹配调色板、导出蓝图」这条流水线，网站上的 2.0 不在该仓库中。E2 按本文的规则自己实现。不嵌入该项目的代码，也不使用 ObjToSchematic 或其作者的名字为本项目背书。

## E1：行走精修

### 目标

用户能走进已有建筑，用画面中心的准星放置、删除和选择内部或背面上的格子。轨道相机继续负责看整体。

当前查看器是 `OrbitControls`：拖动旋转、右键平移、滚轮缩放，以及正视、侧视、顶视、轴测。拾取来自鼠标射线，命中已画出的实例网格；射线未命中方块时落到 Y=0 平面，用于在地面起笔。放置和删除已经提交到 Python 权威场景。

### 操作

界面提供「第一人称」开关，进入后按钮名称为「退出第一人称」：

- 建筑画布铺满窗口，普通工作台顶栏、工具栏与两侧面板收起。指针锁定在画布上，中央显示准星；底部显示当前材料的缩略图、名称与非默认属性，退出快捷键提示始终可见。
- `Esc` 先解除指针锁定并打开浮动编辑菜单，留在第一人称位置。菜单切换材料库或设计工具，可使用属性、选区、分组、预演、剖切、对比与历史；矮窗口下整体滚动，退出按钮固定在顶部。再次按 `Esc` 沿用现在的行为，取消尚未提交的预演。
- 点击菜单中的「退出第一人称」，或按 `G`，恢复进入前的轨道相机位置、目标点、视野和面板布局。临时收起面板不覆盖浏览器原有布局设置。`G` 在输入框、下拉框和文本区里不生效。
- 眼睛高度为 1.62 格，人站在某格地面上时眼睛落在该格往上 1.62 格。相机可以飞进实体方块内部，不做碰撞、重力或惯性，这样墙内和楼板下的格子能够被修到。
- `W` `A` `S` `D` 按当前视线的水平投影移动，视线接近垂直时仍用相机的水平前向，避免垂直抬头后无法水平移动。`Space` 上升，`Shift` 下降。`Ctrl` 将速度从每秒 8 格提高到每秒 16 格。位移按帧时间积分，单帧位移设上限，避免切出页面后一帧飞出建筑。
- 行走时视野改为 70 度。轨道模式恢复现在的 40 度。
- 行走期间 `Shift` 用于下降，扩选改为 `Alt`+点击。界面在行走时把选区提示改成这句话。
- 行走时左右键固定为删除和放置，`Alt`+左键首次选择一格，再次扩选；轨道模式的三种工具暂时禁用，退出后恢复。进入时保留轨道相机的 X/Z 与水平朝向，以场景最低占用层的顶面为初始脚下高度（空场景为 Y=0），眼睛再抬高 1.62 格。
- 左键删除准星命中的已有方块，右键在命中面外侧的空格放置当前材料。放置、删除、选区的语义与现在的鼠标操作相同，包括地面平面起笔。
- 命中距离默认 5 格，超出则视为没有命中方块。距离做成配置。第一版每次点击单独提交一次编辑，使用现有的 `expected_revision` 和 `request_id`。按住连放要等单次往返延迟测完再定，避免一次拖动产生无法合并的大量修订。
- 命中距离通过 Esc 编辑菜单的数字输入配置，必须是有限正数，保存在当前浏览器的 `workbench.walkReach` 设置中；项目不记录它。释放鼠标后可点击“继续编辑”或画布重新锁定并收起菜单，重新锁定的这次点击不编辑。切出页面或窗口会清除按键，回到页面后需重新按移动键。
- 准星拾取调用与 `Viewer.pick` 相同的网格射线，只是射线从屏幕中心发出。没有画出网格的特殊方块，沿用当前点击拾取的限制，并继续显示现有的特殊内容警告。E1 不另做一套体素射线，以免和鼠标拾取结果分裂。
- Y 层剖切、修改前后对比、分组和预演继续有效。剖切只影响显示和拾取可见性，不删除权威场景里的方块。
- 行走相机只存在于浏览器会话。保存的项目不记录相机。P6 截图任务要使用室内视角时显式传 custom 相机参数，不隐式读取用户的行走相机。

窄屏和触控没有指针锁定的可靠行为。E1 的验收目标是桌面 Chrome，与 P5 相同。触控行走不在本阶段。

### 验收

在已有木屋或同等小场景中，用真实 Chrome 完成：

1. 从室外进入行走，飞入室内，放置一格并删除另一格。
2. 服务端修订增加，自动保存后重开，这两格的状态仍在；相机回到轨道视图。
3. 撤销回到行走前的场景。错误的修订号不会在飞行中途覆盖新稿。
4. `Alt`+点击能扩选；`Shift` 只负责下降。
5. 打开 Y 层剖切后，被隐藏层上的方块不能被准星命中。
6. 页面无脚本错误。窄于 720px 时行走开关仍可点到，本阶段不要求手机上完成指针锁定。
7. 第一人称画布覆盖整个窗口；材料菜单修改楼梯朝向后实际放置的完整状态一致。退出后面板布局与原控件位置恢复，临时菜单不改变浏览器的面板设置；640×500 窗口仍能修改选区、滚动工具并退出。

### E1 不做

碰撞和重力、生存模式的手感、物品栏、连放连挖、权威场景里的玩家实体、把 Cubical 的脚本工具或生成器搬过来。

## E2：网格体素化

### 目标

用户提供一份三角网格，工作台按选定高度把它变成 1.20.1 的完整方块，作为一次可预演、可撤销的编辑写入当前项目，并能导出已支持的 `.litematic`。

结果必须仍能逐格修改。体素化不建立第二套场景，也不绕过保护格、区域重叠和修订检查。

### 输入

第一版读取：

- Wavefront OBJ，以及它引用的 MTL 和一张漫反射贴图。
- glTF 2.0 的 `.gltf` 与 `.glb`，使用网格的基色顶点色或基色贴图。

导入前必须展示并经用户确认：

- 模型包围盒在原始单位下的尺寸、三角形数量、是否带顶点色或贴图。
- 轴向。glTF 按 Y 轴向上读取。OBJ 默认也按 Y 轴向上，并提供绕 X 轴 90 度的开关，用来把 Z 轴向上的导出转成 Y 轴向上。确认前在预览里画出包围盒和对齐后的轴向，不静默猜测。
- 目标高度，单位是方块，范围 1 到 256。宽度和深度按比例取整，至少为 1。没有隐式的默认高度。
- 壳或实心。
- 壳厚度，单位是方块，第一版只允许 1。
- 是否启用抖动。
- 写入方式：只填空格，或覆盖目标体积内的已有方块。覆盖仍不能改动保护格。

文件上限 64 MiB。三角形超过 2,000,000 时拒绝并说明数量，不开始体素化。将要写入的非空气格超过 100,000 时拒绝，并提示降低高度。100,000 格与现有扩展基准同一量级，本功能不把尚未验收的更大场景当作成功条件。

不读取骨骼动画、变形目标、多 UV、法线贴图、发光贴图和自发光。网格带这些数据时忽略它们并在确认页列出，不因此失败。

### 体素化

缩放和对齐在取整之前完成。每个方块格是对齐到整数坐标的单位立方体。

1. 将三角形变换到方块空间，并建立 BVH。
2. 壳模式：格子与任一三角形相交则占用。另外把命中沿几何法线膨胀到 1 格厚，使零厚度的墙和地面不会消失。膨胀结果仍要栅格化到整格。
3. 实心模式：先得到壳，再沿 +X 做奇偶射线判断内部。表面格始终占用。开放网格、边界上的射线或无法判定的格子标为不确定，整次导入失败并给出不确定格的数量和示例坐标，不把内部猜成实心。
4. 每个占用格在命中点取色。有贴图时用双线性采样，否则用顶点色，再否则用一个显式的默认中性色并在确认页说明「该网格没有颜色」。一个格子内多个采样在 Oklab 空间取平均。
5. 抖动可选。启用时使用 Floyd–Steinberg，遍历顺序固定为 Y、Z、X，误差扩散到尚未处理的邻居。同一文件字节、同一选项和同一调色板哈希必须得到同一格网。
6. 在调色板中找 Oklab 距离最近的方块。距离相同则取名称字典序较小的方块。

调色板由已导入的 1.20.1 官方资源生成，不手写，也不从其他项目拷贝颜色表：

- 只收支持分类为 static、且模型是单个满格立方体的方块。楼梯、半砖、栅栏、墙、门和其他非满格几何不进入第一版调色板。
- 排除依赖群系染色的方块，以及主贴图为动画的方块。
- 代表色取该方块粒子贴图或朝下表面贴图的平均色，换算到 Oklab，并与资源包哈希一起写入可再生成的调色板文件。
- 羊毛、混凝土、陶瓦等因此会被收进来；某个方块最终在不在表内，以上述规则重新生成为准，不在本文冻结名单。

匹配结果使用该方块的默认完整状态，名称和属性都显式写出。

### 写入场景

确认后的结果是一次编辑事务：

- 先返回预演：将写入的格数、将替换的格数、调色板中实际用到的方块种类、目标包围盒。用户确认后才提交。
- 全部格子一次提交，撤销一步回到导入前。失败时场景和修订都不变化。
- 任一目标格是受保护的方块实体关联格时，整批失败并沿用现有保护错误，不写入其余格子。
- 导入的占用格放入一个新分组，分组名默认 `mesh`，重名时加序号。分组只是选择便利，格子之后仍可逐格编辑、移出分组。
- 新格子落在现有区域外时，沿用现在的包围盒规则。与已有区域产生重叠歧义时，导出阶段继续失败并报告 `EXPORT_REGION_OVERLAP`，导入本身不悄悄合并区域。
- CLI 和 HTTP 调用同一个应用服务。浏览器只负责选择文件、收集选项和展示预演。OBJ、glTF 和贴图解析放在格式适配器；取色、体素化和最近色匹配是纯函数；场景服务负责预演和提交。领域模块不读取文件，也不导入三维引擎。

导出走现有 Litematica v6、DataVersion 3465 的路径。独立读取器按格核对导入所写的名称、属性和坐标。

### 验收夹具

夹具使用本项目可重新生成的小网格，不把第三方模型放进仓库：

| 夹具 | 通过标准 |
| --- | --- |
| 轴对齐的 2×2×2 立方体，高度设为 2 | 恰好 8 个满格，坐标与选定原点一致 |
| 六面不同纯色、高度为 1 的盒子 | 每面落到调色板中距离该颜色最近的方块；预期方块名写在夹具说明里 |
| 零厚度的单平面，壳厚度 1 | 得到一层方块，不丢成空场景 |
| Z 轴向上的立方体，打开轴向校正 | 与 Y 轴向上的同一立方体占用相同的相对格子 |
| 开放盒子使用实心模式 | 整批失败，场景修订不变 |
| 目标体积含一个受保护的方块实体格 | 整批失败，相邻空格也不写入 |
| 成功导入后的导出 | 独立读取器逐格核对状态和坐标 |

另外用一份不超过上限的手工网格在真实浏览器里完成：选择文件、看清高度和轴向、预演、提交、撤销、再提交、导出。记录写入格数和耗时。不把这次耗时写成所有模型的性能承诺。

### E2 的后续，不在第一版验收

用楼梯、半砖贴合斜面和薄片，把更多方块的图案纳入调色板，以及按贴图细节保留文字和五官。这些能提高和专用转换网站的接近程度，但每一项都要单独定规则和夹具。第一版不把它们算作 E2 完成。

文生 3D、图生 3D、自动布光、骨骼动画和模组方块不在 E2。

## 实现顺序

E1 和 E2 可以并行。若只排一条，先做 E1：它只动前端相机和现有编辑入口，能先改善精修。E2 新增解析、调色板和事务，适合在 E1 之后单独交付。

两条都遵守 [实施路线](ROADMAP.md) 的交付规则：未满足验收时保持未开始或进行中，不把预览演示写成完成。
