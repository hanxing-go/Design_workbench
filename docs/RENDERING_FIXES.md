# 特殊方块与材质显示修复

日期：2026-10-09。针对水、岩浆、告示牌、床、活塞和染色玻璃的预览问题。性能优化另见 [性能计划](PERFORMANCE_PLAN.md)。

## 修复后的行为

| 内容 | 当前行为 |
| --- | --- |
| 水和岩浆 | 16 种 level 状态的静态表面；按相邻流体计算共享角高度；水使用蓝色染色及透明混合，岩浆使用不受场景灯光衰减的材质 |
| 流体邻接与剖切 | 同类流体之间的内部面由前端隐藏，剖切后可重新显示；跨分块液位变化会更新相邻表面的模型标识 |
| 告示牌 | 11 种木材的落地、墙面、悬挂、墙面悬挂形态；rotation/facing、attached、板面、立杆和链条；使用官方 entity 贴图 |
| 导入告示牌文字 | 从保留的 NBT 提取正反面最多四行文字、颜色和发光标记，生成只读文字预览；不修改源 NBT |
| 床 | 16 色、四向、床头/床尾和床腿，使用官方 entity/bed 贴图；鼠标放置时一次提交两格 |
| 床的编辑 | `set.complete_beds=true` 可自动补齐另一半；两格必须为空，并共同受边界、保护、修订和预算检查；整次编辑可撤销 |
| 活塞 | 修正 blockstate X 旋转方向，以及六面默认 UV、面旋转和 cullface 方向；活塞六向头部和侧面的木条与朝向对应 |
| 染色玻璃/玻璃板 | 使用原贴图 alpha 混合，不再把半透明像素当作不透明颜色；普通镂空材质仍走 alphaTest |
| 缩略图 | 与场景共用材质选择规则，支持上述特殊模型及半透明材料 |

材质来源仍是官方 Java 1.20.1 客户端。活塞的黄色木质条是原版贴图的一部分；修复其方向和 UV，不删除或改画这条纹理。光照、显示器、浏览器颜色管理仍会影响观感。

## 工程边界

`adapters/resources/geometry.py` 管理面坐标和 UV；`special.py` 提供专用静态几何；`atlas.py` 构建图集。`adapters/rendering/fluids.py` 读取邻格，`signs.py` 读取导入附件的文字。领域场景不保存 Three.js 对象，也不把预览几何写回蓝图。

图集配方升级到 2：增加 16 张床和 22 张告示牌 entity 贴图，共 966 张。矩形 entity 贴图保留原尺寸；动画只根据 `.mcmeta` 选择声明的第一帧。使用行式打包和两像素边缘扩展。

资源组合哈希纳入配方版本。旧缓存可在启动时从已解出的素材升级，不需要重新下载 JAR；新目录及指针完成后才切换，旧目录保留。图集迁移不改用户项目。默认关闭 `complete_beds` 时保持旧版编辑请求哈希，可继续重放已保存请求。

半透明格使用独立对象，让 Three.js 按相机深度排序，并关闭深度写入；这会增加绘制调用。本次先修正显示，后续透明批处理须保留正确排序，不能直接和不透明几何合并。

## 验证和剩余限制

自动验证覆盖全部床部件和颜色、全部告示牌状态、16 种流体 level、床的原子放置/碰撞/越界/撤销、旧请求重放、旧缓存迁移、矩形贴图、动画首帧、活塞六向头部及侧面木条、跨分块流体更新。

实际浏览器验证特殊模型进入场景、透明玻璃后方标记对像素产生影响、缩略图、一键放置完整床，以及导入告示牌正反面文字；重新导出的告示牌 NBT 与输入相同。截图保留在被 Git 忽略的 `artifacts/render-fixes/`。

Windows 本地 36 项 pytest、Ruff、strict mypy、TypeScript/Prettier、前端构建及干净 wheel 安装通过。[对应修复的 GitHub Actions](https://github.com/hanxing-go/Design_workbench/actions/runs/37947455111) 中 Windows/Linux 核心与安装检查、Ubuntu 官方资源与真实浏览器测试全部通过。独立 litemapy 重新核对木屋和教堂的全部状态/坐标、教堂 67 个方块实体保留通过。

注册表 1,003 块、24,135 状态的资源审计：23,399 static、655 special、81 invisible、0 missing。static 表示已有静态预览，不等于游戏渲染逐像素一致。其余专用方块仍按原机制显示限制。

水/岩浆没有纹理动画、自动扩散、流向动画或流体更新队列模拟；含水方块保存 waterlogged 状态，但没有叠加水体预览。告示牌字体使用浏览器字体，富文本样式、翻译组件、游戏字体及发光效果只作近似；本次不增加文字编辑。床的原子补齐用于放置工具及显式请求，普通逐格填充/删除仍属于体素编辑，可能产生不完整部件，需结构检查或同时选择完整床。

透明排序采用对象深度；相交透明模型和同一对象内部的复杂三角形仍可能出现混合顺序差异。没有完整游戏光照、群系环境、物理或游戏内客户端加载验收。

## MC 版本

[多版本计划](VERSION_SUPPORT.md) 记录配套要求。工作台架构不要求只能支持 1.20.1，但当前注册表、蓝图校验和专用模型只适配并验证了 Java 1.20.1 / DataVersion 3465。换一个 JAR 并不足以完整支持新版本。后续按项目绑定版本，配套注册表、状态定义、模型纹理、NBT/蓝图适配和测试矩阵；跨版本转换另做显式转换规则及损失报告。Bedrock 与 Java 也不能按同一个版本配置处理。
