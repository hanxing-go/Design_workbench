## P0：项目目标与工程契约

目标：明确建设什么、已有基础是什么、怎样证明完成。

已交付：README、GOALS、CURRENT_CAPABILITIES、SCOPE、ARCHITECTURE、ENGINEERING、ROADMAP。

P0 在最初只交付规划。其后的 P1–P5 已建立独立 Python 实现、资源、Git 仓库与依赖环境；不能把 P0 规划本身当作实现证据。

## P1：可安装的独立工程基础

目标：建立后续能力能够持续维护和验证的基础。

任务：

- P1.1 建立独立 Git 仓库、`pyproject.toml`、`src` 布局、uv 锁文件、开发与可选依赖分组。
- P1.2 明确领域、应用、适配器和接口依赖方向，按正在实现的能力创建文件；配置数据、缓存、日志和临时目录。
- P1.3 统一配置、错误、请求关联和结构化日志，提供 CLI 帮助与环境信息入口。
- P1.4 建立 Ruff、mypy、pytest、依赖方向检查及 Windows/Linux 安装检查的可执行配置。
- P1.5 验证 wheel 在干净环境安装与路径移动；UI 尚未实现时不提供假工作台入口。

验收：锁定依赖安装成功；实际 CLI 帮助和配置读取成功；路径可移动；检查通过；执行不依赖 `ai-mod`、Codex 缓存和原型 Node 模块。

证据：安装/构建日志、依赖检查结果、CLI 运行结果与配置说明。

## P2：版本材料与可解释资源

目标：形成可供人和 AI 共用的材料基础，复用已验证的静态渲染经验。

任务：

- P2.1 建立 1.20.1 注册表与合法状态数据，提供中英文搜索、分页、属性说明；集合核对，不硬编码旧统计值为真值。
- P2.2 建立资源清单与导入缓存，记录来源、哈希、版本及核对状态；不在代码中引用旧研究目录。
- P2.3 解析模型继承、贴图引用、状态变体、组合模型、旋转、UV 与透明规则，输出统一几何与材质描述。
- P2.4 建立缩略图和代表性材料查看页面，验证方块、楼梯、半砖、玻璃、门、活板门、栅栏、墙和植物。
- P2.5 对注册状态生成覆盖分类：普通静态支持、特殊渲染、不可见、缺资源；名称兼容有显式规则和版本范围。

验收：目录集合准确，分页不遗漏，非法状态拒绝；代表性材料几何/方向/贴图核对通过；缺项可见且不会静默替换；资源路径移动后仍能使用。

旧小屋为 1.21.1 演示，教堂有自己的 DataVersion。各自作为标明版本的研究回归样例；另建立或核验 1.20.1 小屋样例。不能只改样例版本字段使其满足基线。

证据：资源清单、目录与状态核对报告、代表性截图、兼容映射说明和覆盖报告。原型查找无缺项只证明对应样例，不替代本阶段验收。

## P3：权威场景与可靠编辑

目标：修改、保存、历史和恢复保持一致。

任务：

- P3.1 建立整数局部坐标、完整方块状态、分块索引、选区、分组与独立实体/NBT 关联模型。
- P3.2 用 SQLite 保存元数据、分块、编辑差异与历史，记录独立数据 schema 版本。
- P3.3 实现设置、填充、删除、替换、移动、复制、Y 轴旋转与镜像；方向属性与部件关系有明确支持规则。
- P3.4 实现预演差异、原子提交、`expected_revision` 冲突、`request_id` 幂等、撤销/重做和单调修订。
- P3.5 通过 CLI 操作同一应用服务；验证重开、异常退出、写入竞争、迁移备份与恢复。

验收：创建小屋—局部修改—撤销重做—保存重开，逐格状态一致；错误批次无部分写入；重试不会重复修改；旧修订不能覆盖新稿；恢复后数据和历史一致。

实体/NBT 不能随变换悄悄脱离所属方块。无法正确处理的变换先明确拒绝并保持原稿，不宣称已支持。

证据：事务、历史、故障与迁移测试，CLI 实际请求结果，存储与操作契约。

## P4：蓝图导入导出与建筑预览

目标：已有建筑可以独立读入、查看、保存和正确导出。

任务：

- P4.1 验证并选择 Python NBT 实现；先开放经过样例验证的 Litematica v6 范围。
- P4.2 处理多区域、有符号尺寸、调色板、跨 64 位状态打包、空气、长整数与标签类型。
- P4.3 为方块实体、实体、未知标签记录保留范围与编辑限制；受限输出必须返回具体损失报告。
- P4.4 实现导入当前场景与安全导出；与独立读取器逐格对照状态、坐标及声明保留的 NBT 内容。
- P4.5 建立只读三维查看器：实际模型与贴图、多角度、剖切、前后版本查看；前端资源随包交付。
- P4.6 记录小型建筑、36,094 格教堂的载入、预览、保存和导出基线；建立目标机器说明和后续发布阈值。

验收：教堂全部占据格被导入，状态与坐标回读一致；复杂内容无静默丢失；真实浏览器无资源查找失败；版本不匹配明确报告。预览的成功不代替交互编辑验收。

未知内容只在经过验证的范围内保留。对会改变未知数据关联的编辑，返回限制或使用明确的只读保留模式，不承诺任意修改后仍完全无损。

证据：独立格式对照报告、内容保留报告、实际预览截图、浏览器日志及固定机器性能基线。

## P5：可交互的三维设计工作台

目标：用户在界面中完成真实设计流程，交付点 A 达成。

任务：

- P5.1 材料面板、属性面板、点击/区域选择、分组树与相机操作。
- P5.2 放置删除、填充替换、移动复制、旋转镜像、变换预览、撤销重做和修改差异显示。
- P5.3 分块增量传输与网格更新；可复用几何、遮挡面处理和透明内容按实际支持范围验证。
- P5.4 在基础编辑稳定后增添阵列、轮廓挤出、圆弧及参数化屋顶/窗组；生成结果仍可逐格编辑。
- P5.5 建立明确范围的门床多格、楼梯/墙/栅栏连接检查；规范化建议先显示差异，保留超出规则范围的提示。
- P5.6 记录用户通过 GUI 完成建主体、改屋顶、调窗、撤销重做、保存重开和导出的流程。

验收：UI 真正改变 Python 权威场景；教堂规模下局部编辑与保存通过 P4 预先记录的门槛；人工检查代表性方向、贴图、透明和开口。对高级工具逐项记录支持范围。

证据：浏览器端到端结果、前后截图、修订与导出对照、性能复测及已知限制。

## P6：AI 工具与真实视觉反馈

目标：外部 AI 能使用工作台，交付点 B 达成。

任务：

- P6.1 为材料查询、场景检查、选区、预演、提交、历史和导入导出提供版本化 MCP 工具。
- P6.2 `render.views` 返回实际 PNG、多视角/剖切、相机、设计修订；与用户 UI 共用渲染器。
- P6.3 渲染固定修订或场景快照，处理模型等待期间的修改；AI 提交旧修订时要求重新观察。
- P6.4 工具有操作数量、空间范围、响应体积与执行时间限制，错误指明对象或字段。
- P6.5 验证 CLI、HTTP、MCP 使用相同应用服务；截图任务有托管浏览器依赖、超时、取消和失败结果。

验收：真实外部 AI 客户端完成材料查询—创建建筑—读取实际画面—局部改稿—导出；用户同时修改导致的冲突可检测；工具重试不重复执行。

不要求平台此时自行选择和调用模型。无实际客户端或只有 mock 验证时，相关项保持待验收。

证据：工具契约与客户端版本、实际调用记录、PNG/修订对应记录、契约与端到端结果。

已实现 CLI 优先、HTTP/MCP 共用的 15 个工具；真实客户端完成 838 格木屋起稿、读图后修订为 870 格并独立核对导出。截图支持冻结快照、并发冲突、超时取消和资源预算。使用方式见 [P6_USAGE](P6_USAGE.md)，最终验收状态见 [P6_ACCEPTANCE](P6_ACCEPTANCE.md)。

## P7：自主设计与局部改稿

2026-10-10 进展：P7.3/P7.4 的外部 AI 控制已经落地，包含阶段/模型/实际用量记录、工具与活动时长预算、取消/继续、永久候选稿和用户改稿确认。模型计数由外部实际累计回报，不能控制外部程序已发出的模型请求。苦情巨树和迪迦案例已经证明外部创作可行；这些案例不代替 P7.1/P7.2 的平台内模型调度或 P7.5 原定三类任务各三次验收。使用与验证见 [AI_CONTROLS](AI_CONTROLS.md)。

目标：平台接收自然语言需求，在有界流程中驱动模型创作。

任务：

- P7.1 建立独立模型适配层，配置可用连接；不把供应商 SDK 引入领域模块。
- P7.2 按设计阶段调度模型：理解需求、规划布局、批量编辑、看实际图像、局部修订；方块展开和普通编辑由确定性程序执行。
- P7.3 设置模型调用、token/成本、耗时、工具次数与改稿轮次预算，支持取消、超限停止、错误恢复和继续运行。
- P7.4 候选稿与短期撤销分开，保留需求、工具差异、截图、模型版本和费用记录；支持用户选择、反馈及继续修改。
- P7.5 记录三类任务：木屋、带塔楼的两层建筑、已有建筑局部改稿；每类至少 3 次独立运行，报告成功与失败，防止只选最好的结果。

验收：先固定需求约束和预算，三类任务各至少产生一份满足必选约束且经人工确认可用的候选稿；实际完成从新需求创建、图像驱动局部修订及最终导出。预算、取消、失败恢复通过实际流程验证；失败记录保留，反复结构性失败的任务类别保持未完成。

评价分别记录需求约束、入口/空间、比例、轮廓、材料搭配和人工审美反馈。自主流程的可靠性与审美满意度分开；不承诺所有风格或每次运行都成功。

证据：实际模型运行记录、任务与预算配置、候选稿、前后画面、成本统计和人工反馈。模型未配置或未实际运行时不宣称自主设计完成。

## 每阶段统一交付规则

每次交付必须提供：

1. 完成任务编号及当前阶段状态。
2. 可运行产物与使用方法；本次 P5 交付见快速开始和验收记录。
3. 可重复的验证命令、环境、数据版本与结果位置。
4. 不支持的内容、失败案例和遗留问题。
5. 下一阶段入口及仍待解决的依赖。

存在未满足的验收条件时保持进行中或待验收。范围调整写入目标/范围/路线并重新验收，不通过改名把失败项算作完成。

## 迁移与扩展

旧原型保留原位，按功能和行为逐项移植；Python 不包一层再调用旧 Node.js。小型来源明确样例可以移入测试夹具，大型资产与贴图通过清单管理，不依赖旧目录的绝对路径。

后续多版本、特殊渲染、复杂 NBT 编辑、建筑资产库和更大规模性能按独立任务扩展。bot 施工只消费导出资产；当前没有施工实现计划。

E1 行走精修和 E2 网格体素化是 P5 之后的独立扩展，不阻塞 P6–P8，也不以 P6–P8 为前置。行为、任务和验收见 [扩展计划](PLANNED_EXTENSIONS.md)。完成 E1 或 E2 不改变交付点 B、C 的状态。
