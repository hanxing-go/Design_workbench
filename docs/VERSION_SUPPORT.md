# MC 多版本扩展方向

当前已实现和验收：Minecraft Java 1.20.1，DataVersion 3465。架构可以扩展其他版本，但修改 `minecraft_version` 不会自动获得完整兼容。当前缺少对应注册表的版本会明确返回 `UNSUPPORTED_VERSION`。

## 按项目绑定版本

每个项目固定 edition、游戏版本、DataVersion、资源包组合哈希和格式适配版本。材料检索、编辑校验、预览和导出使用同一组配置。服务需要支持按项目加载目录和版本配置；目前服务启动时加载单一注册表，这一部分尚未改造。

## 增加一个版本的步骤

1. 导入有来源和固定哈希的方块注册表，校验默认状态、属性和值，确认名称变化与新增方块。
2. 获取对应官方客户端和语言资产，适配模型/贴图布局变化；按版本隔离图集缓存。
3. 检查专用渲染规则，包括流体、床、告示牌及该版本新增的特殊方块。
4. 适配 `.litematic` 格式版本、MinecraftDataVersion、方块实体 NBT、实体及未知内容保护策略。
5. 运行全状态资源审计、典型模型浏览器验证、导入/编辑/保存/撤销/导出和独立读取器核对。通过后才加入界面的可选版本列表。

先选择一个具体 Java 版本完成这一流程，再扩展版本矩阵。Java 版本之间的细小更新也要核对 DataVersion，不能只按 `1.20` 或 `1.21` 大版本声称兼容。

## 跨版本转换

“分别支持两个版本”与“两个版本的蓝图可以相互转换”是不同能力。转换需显式映射改名方块、变化的属性和方块实体字段；目标版本没有的内容不能直接丢弃。应先预演转换、记录损失/替代，再创建目标版本项目并保留原稿。不得仅改 DataVersion 冒充转换成功。

Bedrock 的方块标识、状态、资源与格式需要独立适配。模组方块还依赖模组注册表和资源，也不属于自动兼容。

此文是后续计划，本次没有增加可用 MC 版本，也没有实现跨版本转换。
